# VS Code extensions

Small VS Code extensions, one folder each. Each works in any VS Code window, and builds and installs on its own.

- `html-preview/`: opens any HTML file rendered in a normal editor tab, redrawn on every change to it or a local script it loads. "Reopen With > Text Editor" shows the source.
- `flow/` (Flow v2's window extension, id `adrian333dev.flow`; named workspace-projects before 0.10.0 and project-colors before 0.7.0, whose `workspaceProjects.*` and `projectColors.*` settings are still read and renamed): in a window opened on one folder holding several projects (each a git repo in a top-level subfolder, never a dot-folder such as the workspace's own `.flow`), paints the window in the colour of the project whose file is in the active tab; terminals leave it alone; with nothing open, the pick's colour (none for "All projects"). A file of the workspace itself, in no project, shows the workspace's name and its own colour (`flow.color` in the window's settings, from 0.12.0), else the window's own colours. It writes the window's colours itself, one `workbench.colorCustomizations` write per paint, the bars as [Peacock](https://github.com/johnpapa/vscode-peacock) painted them (Peacock replaced in 0.5.0: two writers echoed each other). Each colour has an accent, a bright colour paired with it: the status bar shows the project's name on the accent, black or white text by contrast, as far left as an extension can (right after the `WSL: Ubuntu` item), and the active tab's bottom line, the activity bar's active line and the active terminal's mark in the terminal list (`terminal.tab.activeBorder`) take the accent too; the activity bar's counts are a light neutral, since most accents share their colour's hue and would blend into the bar. With Flow v2's VS Code patch, the Explorer's header names the pick (`READER`, `ALL PROJECTS`, `WORKSPACE FILES`). Each project's colour stays in its own `.vscode/settings.json` as `flow.color` (Peacock's `peacock.remoteColor`/`peacock.color` still read), with its accent beside it as `flow.accent`, where Flow v2's terminal band reads it. Commands, under "Flow:" in the command palette: "Set up this workspace" turns it on and gives projects without a colour a free one from the favourites; "Change this project's colour" (also on a project folder's right-click menu) picks a favourite or takes a typed colour, the only way a colour changes. The favourites, `flow.favorites`, are 17 dark colours, each with its accent; a colour outside them gets an accent derived from its hue (HSL S80% L60%, silver for a grey). Paints run one at a time, the latest asked for winning; the "Flow" output channel logs each with its cause. Its terminal profile "bash (Flow)" (the machine's default shell) gives each terminal its own `FLOW_TERMINAL=<uuid>`; VS Code revives a terminal with that same environment, so Flow v2 can resume the terminal's Claude Code session after a window close or a reboot. Not the default for now: as the default it broke terminal reattach on reload (Flow v2's TASK-21). "Switch project" (always in the palette, a button in the Explorer's title bar, a click on the project badge, `Ctrl+Alt+P`) lists each project by its folder (`reader/`), "All projects", and "Workspace files"; it shows the one picked (only the workspace's own files) through `files.exclude` in the window's settings, so the real Explorer keeps rename and drag and drop; search and Ctrl+P keep every project (`search.exclude` set `false` for each hidden folder), only the entries it wrote are removed, a folder added at the top while a pick is active hides at once, and opening a file from a hidden project switches to it. Source Control follows the pick (0.8.0): the other projects' Git repositories are closed (a project keeps its own and its `.flow`), and "All" reopens only what the switcher closed. Settings `flow.explorer.followFile`, `.searchEveryProject`, `.hideWorkspaceFiles`, `.sourceControl` (on) and `.paintOnPick` (on from 0.11.0: a pick paints the window, also with no file open). With Flow v2 on the machine, each window opened runs its VS Code patch check and offers to quit VS Code after an update (a reload would keep the old checksums and warn that the installation is corrupt). `node --test flow/tests/*.test.js` runs its tests.

## Install

```sh
./install.sh               # every extension
./install.sh html-preview  # one
```

`install.sh` packages each folder with `vsce` into `.build/` and installs it with `code --install-extension`.
