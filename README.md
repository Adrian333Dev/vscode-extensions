# VS Code extensions

Small VS Code extensions, one folder each. Each works in any VS Code window, and builds and installs on its own.

- `html-preview/`: opens any HTML file rendered in a normal editor tab, redrawn on every change to it or a local script it loads. "Reopen With > Text Editor" shows the source.
- `notepad/`: on hold, not installed, being redesigned (notes in the opened folder, any note linked to a live session). As built: titled notes in groups, in its own sidebar section. Notes are markdown files in each project's `.notepad/` folder (`<group>/<title>.md`), listed under the project's name on its colour; `.notepad/` is committed with the project, so notes sync through its repo. A note whose header holds `session: <id>` is a Claude Code session's draft: Ctrl+Enter in its tab moves the text to `~/.local/state/notepad/outbox/<id>.md` and empties the note, and the session's mod sends it. `node --test notepad/tests/*.test.js` runs its tests.
- `project-colors/`: in a window opened on one folder holding several projects (each a git repo in a top-level subfolder), paints the window in the colour of the project you work in, through [Peacock](https://github.com/johnpapa/vscode-peacock). It follows the active tab's file, or the active terminal's folder; nothing open, no colour. A file or terminal of the workspace itself, in no project, shows the workspace's name and the window's own colours. Each colour has an accent, a bright colour paired with it: the status bar shows the project's name on the accent, black or white text by contrast, as far left as an extension can (right after the `WSL: Ubuntu` item), and the active tab's bottom line and the activity bar's active line take the accent too; the activity bar's counts are a light neutral, since most accents share their colour's hue and would blend into the bar. The title bar is VS Code's own. Each project's colour stays in its own `.vscode/settings.json` (`peacock.remoteColor` under WSL, else `peacock.color`), with its accent beside it as `projectColors.accent`, written whenever the extension paints or sets the colour, where Flow v2's terminal band reads it; the workspace's own settings get none. Commands: "Project colors: Set up this workspace" turns it on and gives projects without a colour a free one from the favourites; "Change this project's colour" on a project folder's right-click menu runs Peacock's own colour commands and saves the result into the project. It also sets Peacock's favourites to 17 dark colours, each with its accent in an extra `accent` field (Peacock reads only `name` and `value`), and the lighter shade to 10%; a colour outside them gets an accent derived from its hue (HSL S80% L60%, silver for a grey). The accent keys Peacock also manages are in `peacock.excludedSettings`, so Peacock leaves them alone. Its terminal profile "bash (Flow)" (the machine's default shell) gives each terminal its own `FLOW_TERMINAL=<uuid>`; VS Code revives a terminal with that same environment, so Flow v2 can resume the terminal's Claude Code session after a window close or a reboot. Not the default for now: as the default it broke terminal reattach on reload (Flow v2's TASK-21). Paints run one at a time, the latest asked for winning. A project's colour changes only through "Change this project's colour": any other colour Peacock writes (it echoes colours the window held a moment before) is put back. The "Project colors" output channel logs each paint with its cause, and each colour Peacock wrote. The active terminal's mark in the terminal list takes the accent too (`terminal.tab.activeBorder`). With Flow v2 on the machine, each window opened runs its VS Code patch check and offers a reload after an update. `node --test project-colors/tests/*.test.js` runs its tests.

## Install

```sh
./install.sh               # every extension
./install.sh html-preview  # one
```

`install.sh` packages each folder with `vsce` into `.build/` and installs it with `code --install-extension`.
